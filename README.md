# CloudMusic Preference Models

基于冻结的 MS-CLAP 音频向量，比较传统机器学习和神经网络的个人音乐口味排序。本文介绍全部实现、评分方式、实验结果和限制。

**本仓库仅包含源代码。** 不包含训练音频、喜欢清单、播放记录、标签数据、向量缓存、逐曲排行榜、训练日志、模型权重或上游 MS-CLAP 权重。本文只展示汇总指标；运行需提供自己的合法音频和私有数据。

## 任务与分数含义

| 任务 | 训练信息 | 输出 | 评价 |
| --- | --- | --- | --- |
| 口味匹配、候选排序 | 喜欢清单、歌曲特征、行为权重；相对方法另拟合未标记背景库 | 邻域支持度、密度差、去噪增益、参考百分位 | 收藏与未标记曲的检索代理AUC，越高越好 |
| 已收藏歌曲播放强度预测 | 收藏曲中已知的播放次数 | `log(1 + playCount)` | MAE越低越好，Spearman越高越好 |

未收藏、低播放、次数未知都不等于“不喜欢”。背景歌曲是未标记样本，不是确认负例。AUC不是喜欢/不喜欢准确率；任何百分位都不是校准后的喜欢概率。

```text
本地音频 → 统一预处理 → 冻结MS-CLAP 1024维向量 → 原生坐标或训练集PCA
                                                    ↓
喜欢清单＋播放记录 → 行为权重 → 个人模型 ────────→ 排序分 → 参考百分位
未标记曲库 ─────────────────→ 背景模型（相对方法）↗
```

喜欢身份只由自己的 `liked-files.txt` 决定，不能把“有标签”直接视为喜欢。标签描述风格，播放记录描述行为强度。

## 算法简介

### 传统机器学习

这些方法不训练神经网络，但仍使用预训练编码器产生的冻结音频特征。“相对”表示比较个人收藏与背景库的支持程度。

| 算法 | 原理、评分方式 | 权重用法 | 特点与限制 |
| --- | --- | --- | --- |
| 加权KNN | 找最相似的k首收藏，累加余弦指数核支持度 | 近邻贡献乘行为权重 | 能解释具体邻居；高频曲风或通用相似性可能占优 |
| 相对KNN | 收藏近邻对数支持度减去背景近邻对数支持度 | 个人加权、背景均匀 | 比较个人特异性；依赖k、核温度、背景覆盖 |
| 加权KDE | 全部训练收藏组成余弦指数核混合，按有效权重和归一化 | 核混合系数来自行为权重 | 得分平滑；高密度不必然代表偏好强 |
| 相对KDE | 个人核混合密度评分减去背景核混合密度评分 | 个人加权、背景均匀 | 抵消部分通用特征；依赖核温度和背景库 |
| 多兴趣KMeans | 收藏聚成多个兴趣簇，比较候选与归一化簇中心；验证选择硬最大值或带簇质量的LSE软聚合 | 聚类拟合及簇质量使用权重 | 能表达多个口味；簇中心丢失局部细节，硬最大值可能影响跨簇歌曲 |
| 相对Gaussian Mixture | 分别拟合个人和背景的正则化对角高斯混合，取对数密度差 | sklearn GMM无直接权重接口，用加权重采样近似 | 参数少、可复现；分量数和协方差正则影响欠拟合／过拟合 |
| One-Class SVM | 只用收藏学习特征支持区域，按 `score_samples` 排序 | 拟合传入 `sample_weight` | 正样本边界基线；在支持区域内不等于更喜欢 |
| Isolation Forest | 只用收藏训练随机隔离树，按正常程度排序 | 拟合传入 `sample_weight` | 异常检测基线；罕见但喜欢的风格也可能被当成异常 |
| 随机森林回归 | 多棵回归树预测收藏曲播放强度 | 本轮用已知次数作目标、均匀拟合，不重复加入行为权重 | 能预测重播倾向；未知次数不填零，输出不等于新歌喜欢概率 |

入口：[传统实验](genre_model/traditional_preference_experiment.py)、[KNN/KDE维数对照](genre_model/compare_kernel_dimensions.py)。原有 [KNN模块](genre_model/preference_knn.py) 另支持直接融合已有标签、排除自身录音、解释逐邻居贡献，与新相对KNN实验的配置应区分。

### 神经网络与历史对照

这些代码保留用于研究对照。当前传统路线不需要运行它们。

| 算法／变体 | 架构与训练目标 | 输出 | 主要限制 |
| --- | --- | --- | --- |
| MLP播放强度回归 | 冻结向量 → 256 → 64 → 标量；优化标准化播放强度的SmoothL1 | 预测 `log1p(playCount)` | 学重播强度，不是二分类喜欢概率 |
| 基础潜空间个人扩散 | 向量可先PCA降维，再用时间条件残差MLP预测高斯噪声；也支持不投影 | 平均去噪误差及个人参考百分位 | 受尺度、可预测性、通用声学结构影响 |
| 标签条件个人扩散 | 时间嵌入与标签编码通过FiLM调制残差网络，含条件dropout | 条件或空条件下的去噪误差 | 条件可能被忽略；绝对误差不等于审美概率 |
| 相对扩散 | 相同结构的个人、背景去噪模型 | `MSE_background - MSE_personal` | 相对去噪增益代理，**不是精确对数似然比** |
| 连续AR个人模型 | PCA或原生坐标按16维分块，右移输入＋因果Transformer＋4分量对角高斯混合头；优化NLL | 个人对数似然 | 单独似然可能奖励容易建模的统计结构 |
| 相对AR | 个人、背景各训练一个连续AR | `log p_personal(x) - log p_background(x)` | 小样本密度估计、尾部主成分、双模型拟合差异会影响排名 |
| 标签条件相对AR | 标签编码加入各位置Transformer输入，20%整条件dropout | 给定估计标签条件的个人／背景对数似然差 | 条件化不自动等价于建模对标签本身的偏好；本轮未见稳定增益 |
| Top200相对AR | 按行为权重选前200首喜欢曲，再训练相对AR | 同相对AR | 这是训练子集策略，非新网络；测试集变化，不能直接与全收藏AUC比较 |

入口：[MLP](genre_model/train_replay_model.py)、[基础扩散](genre_model/train_diffusion_preference.py)、[条件扩散](genre_model/train_conditional_diffusion.py)、[背景扩散](genre_model/evaluate_diffusion_background.py)、[连续AR](genre_model/train_ar_preference.py)、[Top200](genre_model/train_ar_top200.py)。

最新扩散消融统一为宽256、3层FiLM残差；原先条件扩散为宽512。AR为宽128、2层、4头注意力、4个高斯分量，维数变化时保持每块16维，因此序列长度也变化。跨版本差异不能全部归因于维数或预处理。

## 权重、标签与公式

行为权重保留用户定义：

```text
w_i = 0.5 + L_i + ln(1 + m_i²)   # 次数已知
w_i = 0.5 + L_i                  # 次数未知
```

`L_i` 表示是否进入“喜欢的音乐”歌单，`m_i` 为已知累计播放次数。未知次数不是零。Top200只用权重筛选，入选后均匀训练。

对KNN/KDE，令 `s(q,i)` 为归一化特征余弦相似度，`Kτ(q,i) = exp((s(q,i)-1)/τ)`：

```text
H_knn(q) = log[ Σ_(i∈N_k) w_i Kτ(q,i) / k ]
H_kde(q) = log[ Σ_i w_i Kτ(q,i) / Σ_i w_i ]

S_relative_knn(q) = H_personal_knn(q) - H_background_knn(q)
S_relative_kde(q) = H_personal_kde(q) - H_background_kde(q)
```

背景权重为1。自身及音频余弦大于0.995的参考录音不参与核近邻评分；KDE分母使用相应有效参考权重。此KDE使用球面余弦指数核，不是欧氏空间高斯带宽的同名配置；相对KNN为截断近邻核支持度差。

新标签／权重神经网络消融采用：

```text
personal_loss = Σ_i w_i loss_i / Σ_i w_i
```

个人分支加权、背景均匀，不同时重复做加权采样。历史条件扩散入口采用加权采样，两种实现需区分。

原始标签主要覆盖收藏曲。为避免“有标签＝收藏”的泄露，消融只从训练注释建立共享近邻标签估计器，为全库统一生成条件，训练歌曲排除自身；不直接读取待测曲真实标签或其缺失状态。传统 `audio_tags` 视图把标准化标签估计特征与音频拼接，名义音频／标签权重为75%／25%，再整体归一化。维数表中的数字指音频部分。

这检验的是**训练集估计标签的使用方式**，不能据此认定高质量真实标签无用。

## 评价协议

- 最新传统实验与新PCA神经网络消融使用同一划分：个人训练867、验证161、测试373首；背景训练867、验证161、测试1,845首。已知喜欢曲不会进入背景库。
- 沿用歌手／录音分组。PCA和特征统计量只用训练数据；共享PCA基底用个人与背景训练合计1,734首拟合。
- 每种传统算法按验证代理AUC选择维数、标签视图和超参数，然后报告测试AUC；随机森林按验证MAE选择。
- 全库榜含4,277首及训练身份。观察新歌推荐优先看背景留出候选榜。
- 百分位参考为验证收藏曲。参考集有限，多首歌可以同为100分；排序仍按原始分数。
- 这是单随机种子的个人数据实验。留出集已被多轮查看，结果属于探索性对照，尚不能替代新的盲评歌曲和人工偏好判断。
- AUC不直接衡量榜首多样性、节奏分布或某首歌是否合口味。高AUC和少量核查曲分数合理，不足以证明榜单没有偏置。

## 音频特征与限制

- 最新链路：16kHz单声道 → 两遍loudnorm（目标−16 LUFS、−1.5 dBTP、LRA11）→ 中间7秒，短音频循环补齐 → 重采样44.1kHz适配MS-CLAP音频塔 → 1024维向量。
- 重采样不恢复16kHz处理移除的高频；响度目标不保证每首实测值精确相同。
- 目前仍只用中间7秒，歌曲结构差异会造成抽样偏差，尚未实现全曲多窗口聚合。
- PCA只在训练集拟合，不等于知道哪些维度最代表个人口味。保留方差与推荐效果不同。
- 各方法可能对通用声学结构、局部密度、尾部主成分敏感。尚未用统一BPM统计验证哪些方法存在或消除了慢节奏偏置。
- 本轮相对KNN/KDE的候选构成更分散，但尚无独立人工盲评证明其更符合真实审美。

## 环境与私有数据

Python 3.11，音频预处理需PATH中的ffmpeg。传统实验使用numpy、scipy、scikit-learn、joblib、threadpoolctl；音频编码及神经网络另需PyTorch等依赖。可先按显卡安装合适的PyTorch，再安装完整依赖：

```powershell
python -m pip install -r requirements.txt
cd genre_model
$env:PYTHONIOENCODING='utf-8'
```

MS-CLAP使用上游 `microsoft/msclap` 的2023音频塔，权重需按上游许可自行获取并缓存；离线编码器不自动下载。缓存包含 `paths`、`vectors`、`model_id`、`preprocess_id`；`model_id` 为 `msclap:2023`，原生为1024维。`MSCLAP_CACHE`、`MSCLAP_PREPROCESS_ID`、`MSCLAP_VECTOR_DIM` 必须匹配缓存。

默认根目录为 `genre_model/` 上级，部分基础入口支持 `MUSIC_ROOT`；研究脚本保留原实验目录约定，并非全部支持该变量。私有布局示例：

```text
dataset_v3/labels_liked_files_20261029.json   # 自己的喜欢歌曲元数据
ncm-playback-dl/tmp/liked-files.txt           # 喜欢歌曲文件名，一行一个
ncm-playback-dl/tmp/signals_final.json        # 自己的歌单／播放记录
genre_model/cache/                          # 自己的向量缓存
models_archive/                             # 自己的模型、划分、日志、排行榜
```

标签JSON为对象数组，含 `文件`、`歌名`、`歌手`，可提供 `风格`、`风格细分`、`语种`、`BPM`、`时长秒` 等。缺失保留缺失，不根据标题猜语种。保守关联规则见 [preference_data.py](genre_model/preference_data.py)。

## 运行入口与产物

**研究入口依赖自己的缓存、既有划分和本地实验产物。** 运行前查看脚本顶部路径及依赖并替换为自己的数据。每次用新输出目录，GPU训练串行执行，batch按显存调整。

### 传统方法

```powershell
python -m unittest test_traditional_preference -v
python traditional_preference_experiment.py
python compare_kernel_dimensions.py
```

传统实验保存验证搜索表、模型、指标、全库榜、留出候选榜、比较图及日志；逐维数脚本另导出24组榜和固定参数对照。传统方法没有梯度学习率，不生成虚构LR曲线。

### 基础训练与历史对照

```powershell
python preference_knn.py train --cache <自己的缓存.npz> --out <新的KNN目录>
python train_replay_model.py --model <KNN目录> --out <新的MLP目录>
python train_random_forest.py --model <KNN目录> --out <新的RF目录>
python train_conditional_diffusion.py --model <KNN目录> --out <新的个人扩散目录> --epochs 360 --patience 360 --batch-size 256
python evaluate_diffusion_background.py --personal <个人扩散目录> --out <新的背景扩散目录>
python train_ar_preference.py --split-experiment <背景扩散目录> --out <新的AR目录> --no-projection --dimension 1024 --chunks 64 --batch-size 256
python train_ar_top200.py --knn-model <KNN目录> --background-ar <完整AR目录> --cache <原生1024维缓存.npz> --out <新的Top200目录>
```

AR复用背景扩散的个人／背景划分；Top200保持其他已知喜欢曲在背景库之外。
